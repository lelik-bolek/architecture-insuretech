# Задание 2. Динамическое масштабирование контейнеров в Kubernetes

## Описание проекта

В рамках задания реализован механизм автоматического горизонтального масштабирования (Horizontal Pod Autoscaler) для микросервиса `scaletestapp`.

Основная цель — обеспечить стабильную работу сервиса в периоды пиковой нагрузки за счёт динамического добавления дополнительных реплик при превышении заданного порога использования ресурсов, оптимизируя утилизацию инфраструктуры без постоянного перерасхода памяти.

---

## Структура файлов и назначение артефактов

```text
Task2/
├── deployment.yaml           # Манифест развёртывания тестового микросервиса
├── service.yaml              # Сетевой интерфейс (NodePort) для доступа к сервису
├── hpa.yaml                  # Конфигурация горизонтального автомасштабирования
├── locustfile.py             # Сценарий генерации HTTP-нагрузки
├── 01_before_load.log        # Лог исходного состояния кластера до подачи трафика
├── 02_scaled_under_load.log  # Лог фиксации масштабирования под нагрузкой
└── README.md                 # Документация по выполненной работе

```

### Назначение файлов конфигурации

* **`deployment.yaml`**
Описывает развёртывание микросервиса на базе образа `ghcr.io/yandex-practicum/scaletestapp:latest`. В манифесте зафиксированы параметры:
* Начальное количество реплик: `1`.

* Запрос ресурсов (`requests`): `memory: 20Mi`, `cpu: 50m` — базовый уровень, от которого вычисляется относительный процент потребления.

* Лимит ресурсов (`limits`): `memory: 30Mi`, `cpu: 200m` — максимальный порог изоляции согласно условиям задания.

* `imagePullPolicy: Never` — политика использования локально загруженного образа внутри кластера.

* **`service.yaml`**
Предоставляет точку входа для трафика к подам `scaletestapp` по порту `8080` через сетевой шлюз типа `NodePort` (порт узла: `30080`), обеспечивая приём входящих HTTP-запросов от утилиты нагрузочного тестирования.
* **`hpa.yaml`**
Конфигурация контроллера `HorizontalPodAutoscaler` (API `autoscaling/v2`):

* Целевой ресурс: `Deployment/scaletestapp`.

* Границы масштабирования: от `1` (минимально) до `10` реплик (максимально).

* Метрика и порог: `averageUtilization: 80%` по оперативной памяти (`Resource: memory`). Как только среднее потребление памяти репликами превышает 80% от запрошенных 20Mi (>16 Mi), контроллер инициирует добавление реплик.




* **`locustfile.py`**
Скрипт на Python для инструмента нагрузки Locust. Эмулирует интенсивный поток пользователей, отправляющих запросы методом `GET /` на порт `8080`, что приводит к росту использования памяти контейнером.



### Назначение артефактов (логов)

* **`01_before_load.log`**
Фиксирует базовое состояние системы в покое (до запуска Locust):
* Работает ровно 1 под (`scaletestapp-6c456b7cbd-zmrqt`).
* Потребление памяти подом составляет 5 Mi.
* Контроллер HPA фиксирует утилизацию `memory: 26%/80%`, число реплик равно `1`.


* **`02_scaled_under_load.log`**
Подтверждает факт успешного срабатывания автоматического масштабирования при подаче нагрузки:
* В результате работы генератора запросов утилизация кратковременно превысила порог в 80% (достигнув пика 114%).
* Контроллер HPA инициировал событие `SuccessfulRescale`, увеличив размер пула до `2` реплик.
* В блоке подов отображаются два активных экземпляра в статусе `Running`.
* Средняя утилизация памяти стабилизировалась на уровне 68%, подтверждая разгрузку сервиса благодаря распределению входящего трафика.

## Порядок воспроизведения

1. Применение манифестов в кластере:
```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
kubectl apply -f hpa.yaml

```


2. Снятие базового профиля до нагрузки:


```bash
{
  echo "=== DATE: (date) ==="
  echo "=== PODS ==="
  kubectl get pods -l app=scaletestapp -o wide
  echo "=== HPA ==="
  kubectl get hpa scaletestapp-hpa
  echo "=== TOP PODS ==="
  kubectl top pods -l app=scaletestapp
} > 01_before_load.log

```

3. Запуск нагрузочного теста Locust:

```bash
locust -f locustfile.py

```

* Host: `http://localhost:30080`
* Users: `500`
* Spawn rate: `50`

4. Фиксация результата автомасштабирования в лог:

```bash
{
  echo "=== DATE: (date) ==="
  echo "=== HPA (SCALED) ==="
  kubectl get hpa scaletestapp-hpa
  echo "=== PODS (SCALED) ==="
  kubectl get pods -l app=scaletestapp -o wide
  echo "=== TOP PODS ==="
  kubectl top pods -l app=scaletestapp
  echo "=== HPA DESCRIBE EVENTS ==="
  kubectl describe hpa scaletestapp-hpa | grep -A 10 "Events:"
} > 02_scaled_under_load.log

```
